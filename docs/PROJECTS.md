# Noe Projects and Packages

Noe projects use Noe-native project metadata.

## Layout

```text
myapp/
├── project.noe
├── src/
│   └── main.noe
└── noe.lock
```

## `project.noe`

Example:

```noe
project {
    name: "myapp"
    version: "0.1.0"
    entry: "src/main.noe"
}
```

The manifest is parsed in a restricted deterministic mode. It is project metadata, not arbitrary code execution.

## Lockfile

`noe.lock` is generated by the toolchain. It records deterministic project metadata and is intended to become the base for content-hashed dependency resolution.

Generate it:

```sh
./build/noe lock
```

## Packages

Remote package downloads and a public package registry are not implemented yet. The package manager currently focuses on project metadata and deterministic lock generation.

Future package goals:

- content-addressed package archives;
- signed packages;
- deterministic dependency resolution;
- target metadata;
- generated API schemas;
- package documentation;
- native artifact verification.

## Why no TOML?

Noe projects intentionally use `project.noe` so the ecosystem remains consistent and readable without mixing a second configuration language into normal Noe work.
