Small language.
Wide capability.

Noqeri keeps the source language deliberately simple—functions, values, control flow and calls—then lets hosts provide advanced capability through a versioned boundary instead of exposing pointers, raw memory or platform intrinsics.

One small core. One explicit escape hatch.

The stable grammar and NIR do not need to learn every operating-system, database, network or device concept. Those capabilities cross one narrow runtime interface.

No pointer language

No address-of, dereference, pointer arithmetic, raw memory reads or volatile operations are required to call native capability.

Calls stay calls

host("app.lookup", id) lowers through the same NIR call operation used by ordinary functions.

Versioned boundary

Hosts exchange only tagged primitive values through a public C ABI. Compiler-internal C++ layouts stay private.

Freestanding remains honest

The native bootstrap rejects runtime-host-dependent builds instead of emitting binaries with unresolved service symbols.

Advanced outside. Simple inside.

The reference runtime ships a few useful services through the same mechanism embedders use. New capability can be added without broadening everyday Noqeri syntax.

Built-in runtime services

  • print(value) — console output
  • platform() — current host family
  • clockMillis() — wall-clock milliseconds
  • textLength(text) — string byte length
  • host(name, ...) — embedding-defined service dispatch

ABI v1 guarantees

  • Explicit ABI version
  • Null, bool, int, float and string tags
  • Length-delimited strings
  • Named function table
  • Host-owned user data
  • No AST/NIR/STL structures in public layout
Design rule: when Noqeri needs more power, prefer a service behind the ABI before adding a new low-level language construct. Syntax should grow only when the concept belongs in programs everywhere—not merely because one host can do it.
